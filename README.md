# ОСИСП, лабораторная 4, вариант 22

Трёхступенчатая система обработки заявок. Semaphore ограничивают FIFO-очереди,
Critical Section защищают очереди и статистику. Сравниваются общая секция
статистики и отдельная секция каждой ступени, 2 и 4 потока на ступень.

STUDENT_ID=109, SEED=1000+109*97=11573. Стандартная нагрузка 500 заявок,
индивидуальная OPERATIONS=500+109*5=1045 заявок.

## Архитектура

Generator (main) → Q0 → Stage1 → Q1 → Stage2 → Q2 → Stage3 → Q3 → Collector.
Каждая очередь имеет собственные CS, Semaphore items и Semaphore spaces.
Основные метрики: завершённые/отклонённые заявки, ожидание и время удержания
секции статистики, время ожидания очередей, занятость рабочих потоков.
Остановка: служебные заявки между ступенями; отдельный Event отменяет все
блокирующие ожидания при ошибке или превышении максимальной длительности.

## План реальных контрольных этапов Git

1. Проектирование: структура, параметры и исходная схема.
2. Базовая реализация: рабочая модель и два режима статистики.
3. Проверки инвариантов, ошибок, ограниченного времени и экспериментов.
4. Данные, графики, анализ и PDF-отчёт.

Коммиты создаются по мере выполнения этапов. Удалённый адрес пока не предоставлен;
публикация контрольных версий и доступ преподавателя требуют отдельной настройки.
